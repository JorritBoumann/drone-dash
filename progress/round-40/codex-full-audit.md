## Findings

1. **High — touch controls can stay engaged after the page loses focus.** [InputController.ts](/Users/jorritboumann/projects/browser-game-lab/games/drone-dash/src/core/InputController.ts:322) clears keyboard and button state on blur, but leaves the virtual stick’s pointer ID and position active; it also doesn’t remove pressed styling from touch buttons. **Reproduction:** on a phone, hold the stick or a climb/boost button, switch apps, then return. The drone can keep receiving stick input, and a button can still look pressed. **Fix:** in `clear()`, release or invalidate the stick pointer, zero its axes, reset the knob, clear all pressed classes, and make pointer capture or a lost-pointer handler release each control.

2. **Medium — a failed `localStorage` access can abort a run.** [Hud.ts](/Users/jorritboumann/projects/browser-game-lab/games/drone-dash/src/ui/Hud.ts:934) has a `try/catch` for slip-hint storage, but [Game.ts](/Users/jorritboumann/projects/browser-game-lab/games/drone-dash/src/game/Game.ts:531) enables teaching for a first run and does not arm that hint; check whether the unguarded access is reachable through the HUD’s other hint path. **Reproduction:** use a browser or privacy setting where storage access throws, then start a run that reaches the affected hint path. **Fix:** guard every storage read and write at the point of access, with an in-memory fallback. Other storage paths I checked—best score, daily score, music preference, zoom, and minimap visibility—already catch storage errors.

3. **Low — disposing the game leaves its music button listener attached.** [Game.ts](/Users/jorritboumann/projects/browser-game-lab/games/drone-dash/src/game/Game.ts:352) adds a named click listener to the music button, but [Game.dispose()](/Users/jorritboumann/projects/browser-game-lab/games/drone-dash/src/game/Game.ts:2497) does not remove it. **Reproduction:** repeatedly hot-reload the app and click the music button; stale game instances can still receive clicks. **Fix:** remove the listener in `dispose()` and use the same cleanup pattern for the other UI handlers.

## Areas checked

Pause/resume and run restart reset the main gameplay timers and input state. Overtime has a bounded timer, and a completed overtime delivery ends the run after a short hold. The main best-score, daily-score, music, zoom, and minimap storage paths handle unavailable storage. I did not find a restart-time GPU resource leak: the city is reused between runs.
